# Signet Technology Selection

## 判断の境界を固定する

1. 依頼が調査・提案だけならコード、CMake、依存、文書を変更しない。採用の明示がある場合だけ実装へ渡す。
2. C++23、Qt 6、CGAL 6.2をSignetの指定基盤として扱い、別の言語、UI基盤、幾何エンジン、パッケージ方式を暗黙に置き換えない。
3. 対応OS、配布方式、保存形式、ライセンス、外部送信境界が未決定なら、候補と決定が必要な点を分けて止める。

## 比較する

1. 目的、正本データへの影響、幾何学的正確性、Qtとの境界、性能、テスト容易性、保守負担、AGPL互換性を比較軸にする。
2. CGAL 6.2へ渡す型、カーネル、丸め・許容誤差、Boolean結果の安定順序を先に確認し、表示都合のデータ変換を正本にしない。
3. Qt 6の画面状態とモデル・コマンド・永続化を分離し、描画API固有の型を保存形式へ漏らさない。
4. 公式一次資料、現行CMake設定、対象テスト、ライセンス文書を根拠にし、ベンチマークや互換性を記憶で断定しない。

## 記録と引き渡し

1. 採用案、代替案、却下理由、未確認事項、移行コスト、必要な検証を正本へ一度だけ記録する。
2. 採用後の変更では、設計、CMake、依存、テスト、配布の影響範囲を列挙してから対応Skillへ渡す。
3. 仕様を増やすための新機能、未承認の依存、クラウド・AI・アカウント機能を選定結果に含めない。
