# Signet Code Health Audit

## 監査範囲を決める

1. `git status --short`、対象C++、CMake、CTest、設計正本を確認し、無関係な差分を保護する。
2. 先に守る契約を特定する。パラメトリック幾何、座標・誤差、保存、Undo/Redo、Qt操作、配布、AGPLを品質指標のために変えない。
3. 変更前比較が必要なら同じcompiler、preset、fixture、warmup、実行回数で基準値を得る。

## 診断し評価する

1. 責務混在、所有権・寿命、モデルと表示の境界、CMake target依存、循環依存、再計算、I/O、テスト不足をコードと再現結果で分類する。
2. clang-tidy警告、行数、診断点数だけで問題や優先度を決めない。正しさ、ユーザーデータ、安全境界、操作停止、反復計算を優先する。
3. 誤検知と判断する場合は既存の防御、入力経路、test、sanitizer結果を根拠にする。説明できない警告を設定除外だけで消さない。
4. 高影響の分割、公開契約変更、依存交換、保存移行は、代替案、失われる知識、移行と検証を示して保留できるようにする。

## 改善と再検証

1. 明示された局所改善だけを小さな単位で行い、純粋処理、状態、I/O、描画、互換処理、共有契約を既存境界へ沿わせる。
2. 性能改善は測定対象だけを変え、cache、保存待ち、外部変更、undo、workspace切替の正しさを回帰testで固定する。
3. clang-tidy・sanitizer・対象CTest・全CTestを変更影響に応じて再実行し、中央値や具体的な警告差分を比較する。
4. `git diff --check`と全差分を確認し、実害、誤検知、保留、変更、未実施検査を分けて報告する。
