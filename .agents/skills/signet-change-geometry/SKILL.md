# Signet Geometry Change

## 正本と契約を確認する

1. 変更前に `git status --short`、`docs/INDEX.md`、幾何モデルの正本、対象C++、CMakeターゲット、テストを読む。
2. 円、円弧、黄金長方形、派生図形、変換、対称、Booleanの意味をモデル側へ置き、Qtの描画結果を正本にしない。
3. 座標系、単位、数値型、精度、許容誤差、縮退時の結果、塗り規則、出力順序を変更単位ごとに明示する。
4. C++23とCGAL 6.2のカーネル・型・APIを現行設定と一次資料へ照合し、未確認の型変換や近似を導入しない。

## 実装する

1. 入力検証、純粋な幾何計算、コマンド／Undo、永続化、表示変換を分離する。
2. Booleanは空結果、接線、重複、ほぼ一致する辺、自己交差、巨大・微小座標を定義し、失敗時に入力や正本を壊さない。
3. スナップ、中心線、角度・黄金比補助は表示上の補助と確定値を分け、確定操作を明示的なコマンドへ記録する。
4. 演算結果の正規化と安定順序を決め、浮動小数点の表示差だけでモデルやUndo履歴が変わらないようにする。
5. 許可されていない新しい図形、保存形式、出力形式、外部サービスを実装範囲へ追加しない。

## 検証する

1. CTestの対象テストで正常系に加え、対称性、接線、重複、空集合、ほぼ一致、自己交差、巨大・微小値、順序安定性、保存往復を確認する。
2. 可能なら厳密カーネルと近似表示の境界を別テストにし、誤差をassertの都合で広げない。
3. 入力拒否、例外・エラー、途中失敗で部分結果が残らないこと、Undo/Redoで同じモデルを再現することを確認する。
4. `cmake --build`、`ctest --test-dir <build>`、必要なsanitizer実行、`git diff --check`を影響に応じて行う。
5. 変更した契約、テスト、未確認の数値限界、他担当が統合時に再確認すべき型や順序を報告する。
